# HES dashboard security, release, and rollback runbook

**Applies to:** the merged Gate.io persisted-feed + Strategy V2 + Mother V2 + News Radar + canonical journal dashboard release in PR #408 (main commit 388d4aa326ce4e678f63400f7ad4b53ae76b7b20).  
**Target date:** 2026-11-19.  
**Current disposition:** HOLD / PAPER-TEST-ONLY / NO_TRADE_ONLY.  
**Runtime status:** the read-only dashboard has been deployed and runtime-accepted on the sole VPS. Trading remains HOLD / PAPER-TEST-ONLY / NO_TRADE_ONLY; no account connection or live order execution has occurred.

## Security boundary

- Dashboard binds to `127.0.0.1:8765`. Do not expose it directly to the public internet; remote access must use an approved authenticated TLS reverse proxy and firewall policy.
- Gate.io public Spot BTC_USDT is the sole canonical chart/analysis source. The browser consumes the persisted reader; it must not call exchange REST endpoints or external chart CDNs.
- Exchange/broker adapters are separate execution concerns. No account credentials, balances, order-submit route, or live execution permission are part of this dashboard.
- Keep `execution_enabled=false`, `orders_placed=false`, and `NO_TRADE_ONLY`; missing source, structure, strategy, mapping, confirmation, or risk evidence must remain fail-closed.
- Use the locally pinned TradingView Lightweight Charts asset.
- Responses must include `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, restrictive `Permissions-Policy`, `Cache-Control: no-store`, and CSP directives `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`.
- Dashboard client JavaScript and CSS are same-origin static assets; inline script/style and inline style attributes are removed. CSP does not allow `unsafe-inline`.

## Canonical Strategy V2 report read boundary

The canonical paper-decision projection reads the existing evaluator report:

`/opt/hes-trade-agent/data/forward/strategy_policy_v2_eval_report.json`

The dashboard service must set `HES_STRATEGY_V2_REPORT_PATH` to that exact absolute path. This is a read-only file under the existing `ReadOnlyPaths=/opt/hes-trade-agent/data/forward` boundary; it is not a write exception. The report must identify `source=gateio_public_spot`, `symbol=BTC_USDT`, the locked V2 policy version, a timezone-aware report update timestamp and the nested market-structure `observed_at` timestamp no more than 30 minutes old, `final_decision=NO_TRADE`, `directional_candidates_blocked_until_gates_approved=true`, `execution_enabled=false`, and `orders_placed=false`. Any mismatch, missing report, or stale report returns HTTP 503 with a fail-closed NO_TRADE response. The dashboard does not recalculate V2, infer outcomes, or substitute the V1 diagnostic path.

The report is generated by the existing paper evaluator. The dashboard only reads it; it must never create, edit, or rotate the report. The Gate.io chart/candle path remains the single canonical market-data source and is not fetched again by this report projection.

## Canonical journal read boundary

The existing Strategy Policy V2 paper evaluator is the canonical writer of the shared journal consumed by the Learning Loop:

`/opt/hes-trade-agent/data/forward/trade_journal_v2.jsonl`

The dashboard systemd unit must set `HES_TRADE_JOURNAL_PATH` to that exact absolute path. The dashboard systemd unit must also set `HES_GLOBAL_MARKET_DATA_ROOT=/opt/hes-trade-agent` so the immutable `/opt/hes-trade-agent/current` code release reads the same shared persisted Gate.io candle files written by the collector services under `/opt/hes-trade-agent/data/forward`; never resolve candle files relative to the immutable release directory. Do not use a release-relative `PROJECT_ROOT/data/forward` fallback: the dashboard is launched through `/opt/hes-trade-agent/current`, which resolves into an immutable versioned release.

The dashboard is a read-only consumer. Keep `ReadOnlyPaths=/opt/hes-trade-agent/releases /opt/hes-trade-agent/data/forward` and grant **no** `ReadWritePaths` exception to the dashboard. The dashboard must never append, edit, truncate, rotate, or lock the canonical journal. The evaluator owns the append-only write path, exclusive lock, fsync, stable evidence-derived event IDs, and duplicate suppression. Its existing lock file remains owned by `sentinelx:sentinelx`, mode `0600`; the dashboard does not access it.

The `GET /api/journal` projection and the canonical `GET /api/strategy-v2` projection are read-only. They validate JSONL integrity, duplicate event IDs, timestamps, outcome separation, Gate.io source identity, report freshness, and the locked V2 decision. They never infer realized outcomes. Decision records must keep `outcome=null` and `closed_at=null`; paper outcomes remain separate append-only records.

The legacy `/api/signal` V1 route is diagnostic compatibility only. The dashboard UI does not poll it, it is not the canonical trading decision, and the read-only service sandbox prevents it from mutating the journal. Do not grant journal write permissions to make that legacy route operational.

## Pre-release gate

1. Confirm the approved repository, branch, exact commit SHA, clean staged release artifact, and the recorded second-pass technical audit by the project pair (owner + assistant). This is an internal audit, not an independent human approval. The GitHub ruleset must match the declared two-person team; if it still requires an unavailable third-party approval, keep HOLD rather than bypassing it.
2. Run the full repository suite and exact-head browser test. Browser evidence must show:
   - displayed OHLC/time/volume values match the API payload;
   - chart values match the Gate.io `global_market_data_reader_v1` API batch; V2 report source/symbol and market-evidence freshness are independently verified;
   - no browser-to-exchange REST request or external chart CDN request;
   - visible candles, no console/page errors, and responsive viewport checks;
   - canonical Strategy V2 remains `NO_TRADE` / fail-closed when report or journal evidence is missing or stale; the legacy V1 diagnostic route is not polled by the UI;
   - the existing V2 evaluator owns journal writes; `/api/strategy-v2` and `/api/journal` are read-only; repeated dashboard polling leaves the canonical journal hash unchanged; the Learning Loop sees the same journal hash.
3. Verify the canonical journal and lock file paths, owner/mode, exact `HES_TRADE_JOURNAL_PATH`, the dashboard's read-only sandbox with no `ReadWritePaths` exceptions, and that the dashboard service cannot write market-data, journal, or report files.
4. Verify freshness, closed-candle integrity, Gate.io source identity, symbol mapping evidence, independent structure/confirmation/risk evidence, execution instrument mapping, access control, service user, firewall, health checks, logs, and monitoring.
5. Verify a staged install and rollback in an isolated environment. Capture exact SHA-256 hashes and command output; do not infer success from CI alone.
6. Do not clean, reset, or overwrite the sole VPS dirty checkout. Do not deploy until the real frontend runtime, approved release target, permissions, exact-head CI checks, and owner-verified two-person ruleset are established. Do not fabricate an independent review or bypass a GitHub rule.

## Controlled release procedure

- Build a release artifact from the exact SHA that passed the required CI checks and the recorded internal technical audit; record its hash and dependencies.
- Install to a new versioned release directory, not over the current release.
- Preserve the canonical journal file and its lock inode. Pre-create the lock file if absent before applying the service sandbox.
- Keep the dashboard loopback-only and paper/read-only. Do not enable any exchange order adapter or collector.
- Install the reviewed service unit with the explicit canonical journal path and no journal write exception; grant only the scoped News Radar StateDirectory under /var/lib/hes-news-monitor.
- Validate `/healthz`, `/api/candles`, `/api/signal`, `/api/journal`, CSP/security headers, same-batch hash, freshness, journal write/readback, deduplication, and `NO_TRADE_ONLY`.
- Switch the service target atomically only after explicit release approval. Keep the previous release, service unit, and configuration intact.

## Rollback procedure

Trigger rollback on failed health check, stale/invalid feed, mismatched source/batch hash, journal write failure, duplicate/conflicting event, unexpected external network request, browser errors, security-header regression, service instability, or any execution-enabled/order-placed flag.

1. Stop only the candidate dashboard service; do not stop the canonical Gate.io market-data feeds or paper evaluator.
2. Atomically point the dashboard service to the previously recorded release and restore the previous service unit. Do not use `git reset`, `git clean`, or overwrite the existing dirty checkout.
3. Start only the previously approved read-only dashboard service.
4. Verify `/healthz`, Gate.io source identity, closed-candle freshness, `/api/journal` read-only projection, canonical journal hash continuity, no order endpoints, `execution_enabled=false`, `orders_placed=false`, and browser/API batch consistency.
5. Preserve the canonical journal and lock file; do not truncate or rewrite either during rollback.
6. Record the failed SHA, previous SHA, timestamps, service state, log excerpt, evidence hashes, and reason. Keep release status HOLD until the project owner and assistant have reviewed the failure evidence and the owner has explicitly reauthorized release.

## Recovery/fault tests required

- Missing/unwritable journal, missing lock file, malformed JSONL, duplicate identity with conflicting content, and partial trailing record must fail closed without fabricating rows.

## Operator access from Termius (SSH local port forwarding)

The dashboard is deliberately loopback-only. Do not publish port 8765.

1. Open the existing saved VPS host in Termius. Keep its existing hostname/address, SSH username and key; SSH port is `9011`.
2. Open that host's **Port Forwarding** settings and add a **Local** rule:
   - Local/source port: `8765`
   - Destination/remote host: `127.0.0.1`
   - Destination/remote port: `8765`
3. Connect the SSH session and keep it connected while viewing the dashboard.
4. In the device browser, open `http://127.0.0.1:8765`.
5. If local port 8765 is already occupied, choose local port `18765` and open `http://127.0.0.1:18765`; leave remote destination host/port unchanged.

Security verification on 2026-11-02: SSH listens on TCP 9011; effective policy has public-key auth enabled, password auth disabled, TCP forwarding enabled, GatewayPorts disabled, X11 forwarding disabled, MaxAuthTries 3. nftables input policy is DROP and permits new SSH TCP 9011 and HTTPS TCP 443; dashboard TCP 8765 is not an inbound allow rule. Dashboard listens only on 127.0.0.1:8765. The local tunnel therefore carries dashboard access inside the authenticated SSH connection without opening a public dashboard port.

Do not change SSH users/keys, enable password auth, add a public 8765 rule, or expose the unauthenticated dashboard via public reverse proxy as part of this procedure.
